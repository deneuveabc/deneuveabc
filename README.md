# 你好，我是 Dennie 👋

内容与本地化产品经理，此前做过同传翻译和交付 PM。目前在看 AI 产品方向的新机会，同时也用业余项目认真练习回答一个问题：

> **AI 到底该在哪里出手，哪里必须留给规则和人工？**

我的项目大多从真实业务场景出发。比如做翻译质量评测，是因为我想弄清楚：AI 给出的地名译文，业务到底能不能直接用？名称译错了、机场代码被改坏了、上下文不够时硬猜了一个答案——这几种错误性质不同，对应的拦截和兜底方式也完全不同。

## 正在推进

- **问间 · 聊天 Agent** `v6.1` · `FastAPI` `GPT-5`
  本地聊天应用，由模型自主决定何时搜索网页、读取页面（最多 3 轮，每轮并行调用工具）。我最在意的是**过程透明**：每一步选了什么工具、读了哪些页面、页面的日期能不能撑起“最新”这个结论，都能在网页里直接展开看。

- **Voyage · 出行内容预翻译工作台** · `DeepSeek` `GPT-5`
  本地全栈原型，把“AI 起草 → 规则校验 → 人工拍板”直接做进产品流程：DeepSeek 负责初译，GPT-5 按六维标准独立评估，人工审核队列逐条把关，合格项手动批量应用。

- **翻译质量评测与反馈修订** `v0.2`
  个人合成数据实验（30 条机场/区域名称样本），跑通“生成 → 规则检查 + 独立 AI 质检 → 反馈修订 → 独立复测”闭环。8 条故意注入的错误已全部检出并修订，人工校准还在进行。也如实记下了一个教训：**译文和参考答案完全匹配，仍可能掩盖代码损坏**。

- **豆豆图纸 · 拼豆图纸生成器** `v1.9`
  把喜欢的图片变成能照着拼的图纸：选尺寸和用色 → 生成 → 微调 → 下载或打印，附带坐标色号、用料清单和近色整理。核心功能纯本地运行；想玩 Q 版可以接 AI 插画，但 API Key 只存在用户自己的浏览器里。

- **AI 翻译方案决策复盘**
  任职期间方案调研的脱敏版，对比内部系统、轻量流程和现有平台的取舍与待验证项。这个边界我会一直说清楚：**它展示的是决策思考过程，不是已上线的成果**。

## 我的工作方式

- 先问清楚**谁在为什么费劲**，再找最小可用的一步：明确哪里用确定性规则、哪里让 AI 起草、哪里必须由人拍板。
- 每个项目都会写明**验证日期、样本规模、实际结果和没做完的部分**。
- 没做完就是没做完。相比包装过的“已完成”，我更愿意让人看到真实进度。
